8 ejercicios tipocon código completo

Cómo usarlos

Los exámenes repiten un puñado de tipos: cuenta de ciclos, TMR0, puertos, tablas e interrupciones. Estos ocho los cubren. Escribe el código a mano antes de abrir la solución: leerlo no sirve de nada.

Problema 1 · Subrutina de retardo por cuenta de instrucciones tipo T4

Enunciado

Para un PIC16F84A a 4 MHz, diseña una subrutina que produzca un retardo de 50 ms por cuenta de instrucciones. Calcula el número exacto de ciclos y el error cometido.
✓Solución completa

Partimos de la rutina base de 249 µs (un bucle con la variable cargada a 82) y la metemos en un bucle exterior de 200 vueltas.

Delay50 movlw d'200' ; 1 CI movwf VAR1 ; 1 CI Atras1 movlw d'82' ; 1 CI \ movwf VAR ; 1 CI | Atras decfsz VAR,1 ; 1/2 CI | bloque de 250 CI goto Atras ; 2 CI | decfsz VAR1,1 ; 1/2 CI | goto Atras1 ; 2 CI / return ; 2 CI

Bloque interior (incluyendo el decfsz VAR1 y el goto Atras1 que lo cierran):

\[1+1+3\cdot81+2+1+2=250\ \text{CI}\]

El 3·81 sale de que el bucle interior se recorre 81 veces completas (de 82 a 1) a 3 ciclos cada una, y el «+2» de la última vuelta en la que el decfsz salta.

Total:

\[N=1+1+250\cdot200+2+2=\boxed{50\,006\ \text{CI}}\]

A 4 MHz cada ciclo dura 1 µs, así que el retardo es de 50,006 ms: un error de +6 µs, el 0,012 %.

Para otros tiempos basta cambiar el valor del bucle exterior: 100 vueltas dan 25 ms, 20 vueltas dan 5 ms. Para un segundo hacen falta tres bucles anidados o llamar 20 veces a esta subrutina.

Los dos errores que más se repiten: contar n vueltas en vez de n−1, y olvidar que en la última el decfsz cuesta 2 ciclos y el goto no se ejecuta.

Problema 2 · Onda cuadrada de 10 Hz con el TMR0 tipo T5

Enunciado

Un PIC16F84A a 4 MHz debe generar en RB0 una onda cuadrada de 10 Hz usando el TMR0. Calcula el preescalador y el valor de precarga, escribe el código y estima el error.
✓Solución completa

1) Cálculo. Periodo 100 ms → conmutar cada 50 ms. El máximo de un desbordamiento es \(T_{CI}\cdot256\cdot DF\):

DF11664128256
máximo256 µs4,1 ms16,4 ms32,8 ms65,5 ms

Sólo DF = 256 llega a 50 ms. Cada cuenta dura 256 µs:

\[n=256-\frac{50\,000}{256}=256-195{,}31=60{,}69\]

Probamos los dos enteros: \(n=61\) da \(195\cdot256=49\,920\) µs (−80 µs) y \(n=60\) da \(196\cdot256=50\,176\) µs (+176 µs). Elegimos n = 61.

2) Código.

Inicio bsf STATUS,RP0 bcf TRISB,0 ; RB0 salida movlw b'00000111' ; T0CS=0, PSA=0, PS=111 (1:256) movwf OPTION_REG bcf STATUS,RP0 bcf PORTB,0 Bucle movlw d'61' movwf TMR0 ; precarga bcf INTCON,T0IF ; borra el aviso Espera btfss INTCON,T0IF goto Espera ; aún no se ha desbordado movlw b'00000001' xorwf PORTB,1 ; conmuta RB0 goto Bucle

3) Error. El periodo real es \(2\cdot49{,}92=99{,}84\) ms, es decir 10,016 Hz: un 0,16 %. Para un LED es irrelevante; para una base de tiempos acumularía 2,3 minutos al día.

Tres formas de mejorarlo: añadir un bucle de compensación de 80 µs, bajar el preescalador y contar varios desbordamientos, o usar un cristal de 4,194304 MHz con el que los números salen exactos.

Problema 3 · Contador de 0 a 99 con displays multiplexados tipo T7

Enunciado

Diseña un contador de 0 a 99 con dos displays de siete segmentos multiplexados y dos pulsadores (incrementar y poner a cero). Asigna patillas, calcula el tiempo de barrido y escribe la lógica.
✓Solución completa

1) Patillas. RB0–RB6 segmentos (compartidos), RB7 habilitación de decenas, RA0 habilitación de unidades, RA1 y RA2 pulsadores con pull-up. Los comunes de los displays van a masa a través de un transistor NPN, para no superar los 25 mA de una patilla.

2) Tiempo de barrido. Con 2 dígitos y 100 Hz de refresco:

\[t_{\text{dígito}}=\frac{1}{2\cdot100}=5\ \text{ms}\ \Rightarrow\ n=256-\frac{5000}{256}=236{,}5\to236\ (5{,}12\ \text{ms})\]

3) El barrido.

Barrido bcf PORTB,7 ; apaga AMBOS antes de cambiar bcf PORTA,0 movf DECENAS,0 call Siete andlw b'01111111' movwf PORTB bsf PORTB,7 ; enciende decenas call Delay5ms bcf PORTB,7 bcf PORTA,0 movf UNIDADES,0 call Siete andlw b'01111111' movwf PORTB bsf PORTA,0 ; enciende unidades call Delay5ms return

Apagar los dos antes de cambiar el patrón evita el efecto fantasma: si no, durante unos microsegundos un dígito muestra el patrón del otro.

4) Los pulsadores, con antirrebote completo:

btfsc PORTA,1 ; ¿pulsado? (activo a 0) goto Cero call Delay20ms ; antirrebote btfsc PORTA,1 ; ¿sigue pulsado? goto Cero ; era un rebote Suelta btfss PORTA,1 ; espera a que se suelte goto Suelta call Delay20ms incf UNIDADES,1 movlw d'10' subwf UNIDADES,0 ; ¿llegó a 10? btfss STATUS,Z goto Cero clrf UNIDADES incf DECENAS,1 ; acarreo a las decenas movlw d'10' subwf DECENAS,0 btfsc STATUS,Z clrf DECENAS ; de 99 a 00

El patrón del antirrebote es siempre el mismo: detectar, esperar 20 ms, confirmar, esperar a que se suelte y esperar otros 20 ms. Sin la confirmación hay pulsaciones falsas; sin la espera a que se suelte, una pulsación larga cuenta decenas de veces.

Problema 4 · Interrupción del TMR0 y del pin INT tipo T8

Enunciado

Diseña un sistema que, usando interrupciones, haga parpadear un LED en RB1 cada 500 ms mientras cuenta los pulsos que llegan por RB0/INT, sin que el programa principal tenga que esperar.
✓Solución completa

1) Tiempo. El máximo de un desbordamiento es 65,5 ms, menos que 500 ms: hay que contar desbordamientos. Con n = 61 y DF = 256 cada uno dura 49,92 ms, y diez dan 499,2 ms.

2) Rutina de servicio. Las dos fuentes comparten el vector 0x004, así que hay que distinguirlas.

org 0x04 movwf W_TMP ; salva W swapf STATUS,0 ; swapf no toca banderas movwf S_TMP btfss INTCON,T0IF ; ¿ha sido el TMR0? goto EsINT movlw d'61' movwf TMR0 ; recarga bcf INTCON,T0IF ; BORRA EL AVISO decfsz VECES,1 goto EsINT movlw d'10' movwf VECES movlw b'00000010' xorwf PORTB,1 ; conmuta RB1 EsINT btfss INTCON,INTF ; ¿ha sido el flanco externo? goto Salir incf PULSOS,1 bcf INTCON,INTF ; BORRA EL AVISO Salir swapf S_TMP,0 movwf STATUS swapf W_TMP,1 swapf W_TMP,0 retfie

3) Inicialización.

bsf STATUS,RP0 movlw b'00000001' movwf TRISB ; RB0 entrada, resto salidas movlw b'01000111' ; INTEDG=1, T0CS=0, PSA=0, PS=1:256 movwf OPTION_REG bcf STATUS,RP0 bcf INTCON,T0IF ; borra avisos antiguos bcf INTCON,INTF bsf INTCON,T0IE ; habilita fuentes bsf INTCON,INTE bsf INTCON,GIE ; GIE el ÚLTIMO

Los cuatro puntos que decide el corrector: comprobar las dos fuentes (pueden coincidir), usar swapf y no movf para salvar STATUS, borrar los bits F y habilitar GIE en último lugar.

Si falta un bcf INTCON,T0IF, el síntoma es inconfundible: nada funciona y el micro parece muerto, porque está entrando en la interrupción miles de veces por segundo sin salir nunca del vector.

Problema 5 · Lectura y escritura en la EEPROM tipo T9

Enunciado

Escribe las rutinas de lectura y escritura de la EEPROM del PIC16F84A y diseña la lógica para que un contador que debe sobrevivir a los apagones no desgaste la memoria.
✓Solución completa

1) Lectura.

LeeEE bcf STATUS,RP0 movwf EEADR ; dirección (venía en W) bsf STATUS,RP0 bsf EECON1,RD ; orden de lectura bcf STATUS,RP0 movf EEDATA,0 ; W ← dato return

2) Escritura. La secuencia es obligatoria y no admite cambios:

EscEE bcf STATUS,RP0 movf DIR,0 movwf EEADR movf VALOR,0 movwf EEDATA bsf STATUS,RP0 bcf INTCON,GIE ; interrupciones fuera bsf EECON1,WREN ; permiso movlw 0x55 ; --- SECUENCIA OBLIGATORIA movwf EECON2 movlw 0xAA movwf EECON2 bsf EECON1,WR ; --- arranca (≈10 ms) EspEE btfsc EECON1,WR ; el hardware lo borra al acabar goto EspEE bcf EECON1,WREN bcf EECON1,EEIF bsf INTCON,GIE bcf STATUS,RP0 return

3) Evitar el desgaste. El contador se lleva en RAM y sólo se vuelca a EEPROM cuando hace falta: al detectar un apagón inminente, tras unos segundos de inactividad, o cada N incrementos.

Las cifras justifican el diseño. Con un millón de ciclos por celda:

\[\text{escribiendo cada 10 ms: }\frac{10^{6}}{86\,400/0{,}010}=0{,}116\ \text{días}=\boxed{2{,}8\ \text{horas}}\] \[\text{escribiendo 100 veces al día: }\frac{10^{6}}{100}=10\,000\ \text{días}=\boxed{27\ \text{años}}\]

Al arrancar conviene comprobar si la memoria está virgen: una EEPROM nueva contiene 0xFF en todas sus posiciones, así que ese valor sirve de «no inicializado».

Problema 6 · Tabla de siete segmentos con retlw tipo T2

Enunciado

Escribe una subrutina que reciba en W un dígito del 0 al 9 y devuelva el patrón de segmentos para un display de cátodo común, y explica cómo funciona.
✓Solución completa
org 0x10 ; con su propio org, lejos de 0x04 Siete andlw 0x0F ; por seguridad addwf PCL,1 ; PC ← PC + W retlw 0x3F ; 0 retlw 0x06 ; 1 retlw 0x5B ; 2 retlw 0x4F ; 3 retlw 0x66 ; 4 retlw 0x6D ; 5 retlw 0x7D ; 6 retlw 0x07 ; 7 retlw 0x7F ; 8 retlw 0x6F ; 9

Cómo funciona. addwf PCL,1 suma W al contador de programa, de modo que la ejecución salta hacia adelante tantas instrucciones como vale W y cae sobre el retlw correspondiente, que devuelve su constante en W y retorna. Es la forma de implementar un vector de constantes en una máquina sin acceso a la memoria de programa como datos.

Los patrones salen de encender los segmentos de cada dígito, con \(b_0=a\) hasta \(b_6=g\). Por ejemplo el 5 enciende a, c, d, f, g:

\[\text{gfedcba}=0110\,1101=\text{0x6D}\]

Para ánodo común hay que complementar todos los valores: el 0 pasa de 0x3F a 0xC0, el 1 de 0x06 a 0xF9, etcétera.

Las dos precauciones: el andlw 0x0F evita que un valor fuera de rango salte a una zona de código cualquiera; y la tabla debe colocarse de forma que no cruce el límite de 256 palabras, porque addwf PCL,1 sólo afecta a los ocho bits bajos del contador de programa.

Problema 7 · Configuración de puertos y límites eléctricos tipo T6

Enunciado

Un sistema tiene cuatro pulsadores en RA0–RA3, ocho LED en PORTB y un motor de 12 V y 300 mA controlado desde RA4. Configura los puertos, calcula las resistencias y explica cómo se conecta el motor.
✓Solución completa

1) Configuración.

bsf STATUS,RP0 movlw b'00001111' ; RA0-RA3 entradas, RA4 salida movwf TRISA clrf TRISB ; PORTB todo salidas bcf STATUS,RP0 clrf PORTB bcf PORTA,4

Los pulsadores llevan pull-up externos de 10 kΩ: PORTA no tiene pull-up internos, sólo PORTB.

2) Resistencias y corriente. Con un LED de \(V_F=2\) V a 5 V y 10 mA:

\[R=\frac{5-2}{0{,}010}=300\ \Omega\to330\ \Omega\ (\text{real: }9{,}1\ \text{mA})\] \[8\cdot9{,}1=72{,}7\ \text{mA}<100\ \text{mA}\ \checkmark\]

Con 20 mA por LED serían 160 mA y se superaría el límite de PORTB: habría que usar un ULN2803.

3) El motor. 300 mA es doce veces el máximo de una patilla, y además a 12 V. Hace falta un transistor como interruptor con tres elementos imprescindibles:

  • Resistencia de base de 1 kΩ, para limitar la corriente de la patilla y saturar el transistor.
  • Diodo volante en antiparalelo con el motor: al cortar, la inductancia genera un pico que destruiría el transistor.
  • Masa común pero alimentaciones separadas; si el motor es grande, mejor un optoacoplador que aísle.

Y un detalle que cuesta horas de depuración: RA4 es de drenador abierto y no puede dar un 1 por sí misma. Hace falta una resistencia de pull-up de 10 kΩ a VDD, o invertir la lógica con un PNP.

Problema 8 · Comparaciones y máscaras en la lectura de un teclado tipo T3

Enunciado

Cuatro teclas están conectadas a RA0–RA3 con pull-up (pulsada = 0), y en RA4–RA7 hay otras señales. Escribe el código que lea sólo las teclas, active el bit 5 de PORTB con la tecla 2 e invierta el bit 0 con la tecla 3.
✓Solución completa

1) Aislar las teclas.

movf PORTA,0 ; los 8 bits andlw b'00001111' ; máscara: conserva 0-3 movwf TECLAS

Sin la máscara, cualquier cambio en los bits altos falsearía la lectura. Como el teclado es activo a nivel bajo, sin pulsar nada el resultado es 0x0F.

2) Tecla 2 → activar el bit 5. Con un solo bit, la instrucción de bit es más corta que la máscara:

btfss TECLAS,2 ; ¿bit 2 = 1 (sin pulsar)? bsf PORTB,5 ; era 0: pulsada

Con máscara serían tres instrucciones: movf PORTB,0 + iorlw b'00100000' + movwf PORTB.

3) Tecla 3 → invertir el bit 0. Aquí sí hace falta XOR, porque hay que conmutar sin conocer el estado:

Tecla3 btfsc TECLAS,3 goto Fin ; no está pulsada movf PORTB,0 xorlw b'00000001' ; invierte SOLO el bit 0 movwf PORTB Espera movf PORTA,0 ; antirrebote andlw b'00001000' btfsc STATUS,Z goto Espera ; sigue pulsada call Delay20 Fin ...

Por qué el bucle de espera: sin él, mientras la tecla esté pulsada el bit se invertiría miles de veces por segundo y el LED parecería encendido a media luz. Hay que detectar el flanco, no el nivel.

La regla de este tema: un bit → instrucción de bit (bsf, bcf, btfsc); varios bits → máscara (AND aísla, OR fuerza, XOR invierte).
